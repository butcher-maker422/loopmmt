Loop lineage · The redesign

Loop 2.0

The redesign — Loop computing reimagined in Minecraft with a fuller display and controls, until the arithmetic proved the game too slow and the architecture left for the browser.

With Loop 1.0 finished, I could see so many places it could be better — so I started building Loop 2.0, taking the ideas from 1.0 and making them more powerful and more flexible. I built out the full display and most of the controls.

Then the arithmetic caught up with the ambition. At the scale Loop 2.0 wanted, Minecraft’s redstone would run at roughly one hertz — far too slow to be any fun to operate. The architecture had outgrown the game it was born in.

That wall is the hinge of the whole story. Rather than fight Minecraft’s clock, the next version left the game entirely for the browser. Loop 2.0 was never finished in Minecraft — but it drew the shape that Loop 2.1, built with an AI in three weeks, would run.

This page holds the one surviving image from that redesign — the architecture display; the gallery is built to take more as they land.

B · Read it at your altitude

Loop 2.0 was the redesign of the Minecraft computer — the same loop ideas from Loop 1.0, rebuilt to be more powerful and flexible, with a fuller display and controls. It was never finished in the game: at the scale it wanted, redstone ran too slowly to be fun, so the design moved to the browser and became Loop 2.1.

Loop 2.0 is the second-generation redesign in Minecraft: the Loop 1.0 primitives (loop-line memory, the value-catching path, the ALU) rebuilt for more capability, with the full display and most of the controls constructed. The blocker was throughput — redstone’s ~1 Hz clock made the intended scale unplayable, so the architecture was ported off the game to the browser as Loop 2.1.
