Jukebox Protocol

A Richer Way To Hear The Music

A quick idea with a precise shape underneath it:

The Prompt

Hey, quick idea- could we build a Jukebox protocol that would allow you to HEAR music better? I imagine something that would have an index of songs and artists and albums, made up of lyrics and sound waves and images for each song, so when I say "play some Avett Brothers", you'd have a richer context to load in. So it'd be like a collection of Context Meshes for each song, but organized like a music collection, which we know how to do now, since we've built our own Music Library app. Let's build that now- Super RCR that, and come out in the end with the Jukebox Protocol made. Be clever- use all of our tools, including the FULL set of new apps found in the repo, when thinking about how to build this. And make the Jukebox callable by either me or you, depending on how we need it. Make it generalized so it's useable and flexible. Look up and down, 8X, FWW(C), and maybe have Wes chair the whole thing so it's hella fun. AX

— Shea Gunther · operator drop, 10.2006

The Moment

“Could we build a Jukebox protocol that would allow you to HEAR music better?” The operator imagines an index of songs built from lyrics, sound waves, and images, so that a casual request like “play some Avett Brothers” loads a genuinely richer context — a Context Mesh per song, organized the way a music collection is.

The precision hides under the casualness. The operator points at machinery the system already has (its own Music Library app) and asks to reuse its structure; he wants the protocol callable from both sides (operator or instance) and general enough to stay flexible; and he asks for the deliberation to be chaired for fun. It is a small idea with a well-specified shape — the kind of prompt that reads as an offhand thought but names exactly what would make the thing good.

The wider frameHearing music better, specified precisely: reuse the collection structure already built, make it callable both ways, keep it general.
