Jukebox Protocol

Hear the Music Better

A quick idea, dropped in the middle of a build — the kind that starts with "Hey":

The Prompt

Hey, quick idea- could we build a Jukebox protocol that would allow you to HEAR music better? I imagine something that would have an index of songs and artists and albums, made up of lyrics and sound waves and images for each song, so when I say "play some Avett Brothers", you'd have a richer context to load in. So it'd be like a collection of Context Meshes for each song, but organized like a music collection, which we know how to do now, since we've built our own Music Library app. Let's build that now- Super RCR that, and come out in the end with the Jukebox Protocol made. Be clever- use all of our tools, including the FULL set of new apps found in the repo, when thinking about how to build this. And make the Jukebox callable by either me or you, depending on how we need it. Make it generalized so it's useable and flexible. Look up and down, 8X, FWW(C), and maybe have Wes chair the whole thing so it's hella fun. AX

— Shea Gunther · operator drop, 10.2006

The Moment

The operator runs music while he works — Pretty Lights to focus, the Avett Brothers in the evening. This prompt turns that habit into infrastructure. When he says "play some Avett Brothers," an ordinary system loads the words; the Jukebox idea is that the system should load the song — its lyrics, its waveform, an image — as a bundle of context, the same way the methodology already bundles working context for a project.

The move that makes it Loop MMT rather than a playlist feature: reuse. The methodology already builds Context Meshes, and the operator had already built a Music Library app, so the Jukebox is not a new mechanism — it is two existing ones composed. "Organized like a music collection, which we know how to do now" is the tell: he is pointing at parts already on the bench and asking for them to be wired together.

The wider frameA good operator prompt often just names two things already built and the seam between them.

The Anatomy

"could we build … that would allow you to HEAR music better?" — the request is framed around the AI's experience, not the operator's convenience. The capitalized HEAR is doing real work: the ask is to widen what the system perceives when a song is named, so its response is grounded in more than a title string.

"a collection of Context Meshes for each song, but organized like a music collection" — the whole design is in one clause. A Context Mesh is the methodology's existing unit of loaded context; a music collection is a shape everyone already understands. The prompt hands the AI both the primitive and the organizing metaphor and lets it derive the rest.

"Super RCR that … 8X, FWW(C), and maybe have Wes chair" — the closing line sets the working mode, not the content: run the deep deliberation, load heavy, keep it fun, and put the board's chaos voice in the chair. It is the operator dialing the room's temperature before handing over the work.

Reading the Operator's Shorthand

The prompt is written in the working vocabulary of the methodology. Here is what the shorthand means:

Context Mesh
A bundle of loaded context the AI reads to reconstruct a working situation — here, one bundle per song instead of per project.
Super RCR
A heavy, multi-round deliberation pass (Recursive Companion Review) run with the full board before committing to a design.
8X
Shorthand for loading the reflex sweeps heavily before a load-bearing move — a "look at everything first" instruction.
FWW(C)
"For Whimsy, With Chaos" — the methodology's rule that play and surprise are load-bearing, not decoration.
Wes
A board member whose lens is chaos and complexity science; putting Wes "in the chair" means run the session in a playful, exploratory register.
AX
A close-out marker on the prompt — "execute autonomously": make the plumbing decisions yourself, only surface the real forks.
