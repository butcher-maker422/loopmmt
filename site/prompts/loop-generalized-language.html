Loop Generalized Language

A Command Language for Operators

A quick brainstorm, carried by the memory of the Loop 2.1 keyboard shortcuts:

The Prompt

OK, quick brainstorm RCR- in the Loop 2.1 computer, we came up with keyboard shortcuts for the Operator to use if they wanted. I want the same thing for here, some kind of code like language that I can use to do things. All common operations and protocols should be be possible- really any operation should be possible, including the injection of text, similar to how programming languages handle text. Look up and down the entire world of programming, both new and old, for lessons, with an eye on developing the Loop Generalized Language, which will be used by Operators to simplify their work and make more complex and complicated operations, carried out both solo and in conjunction with other operators, possible. Do one single RCR, full frame, on this, looking at fractals and thinking of grocery stores and the song Take Five. Think about all the notes on that one, because it's what I am listening to now. Confirm with me that you understand the structure of this prompt before moving ahead. Think carefully and FBD away all problems at all levels, look up and down. Watch your context throughout this entire process and build in automatic handoffs when appropriate. Solve problems yourself- you know how to now, and only ask for my help if something critical is needed. Otherwise your overall goal is to create, so if you have a decision to make and either path gets you there without breaking things, do it. Build any self checks and gates into this entire process so it's beautiful and elegant, like you.

— Shea Gunther · operator drop, 10.2006

The Moment

The operator wants a command language for himself: a code-like syntax that can express any common operation or protocol — really any operation, including injecting text the way programming languages handle strings. He points at the whole history of programming, old and new, as the place to mine for lessons, with one eye on the target: the Loop Generalized Language, used by operators to simplify their work and make complex multi-operator operations possible.

The scope is the interesting part. Not a menu of shortcuts — a language, general enough that any operation is sayable in it, and usable both solo and in concert with other operators. He asks for a single RCR, full frame, and — as with the highest-derivative prompt — a confirmation of the prompt's structure before any work begins.

The wider frame“Keyboard shortcuts” and “a generalized language” are different orders of thing. The prompt reaches for the second: not a fixed set of commands, but a grammar in which new commands can be written.

The Anatomy

“some kind of code like language that I can use to do things … really any operation should be possible, including the injection of text” — The core ask: generality. A fixed shortcut list would be easier, but the operator explicitly wants a language — something in which operations that don't exist yet can still be expressed.

“Look up and down the entire world of programming, both new and old, for lessons” — Ground the design in prior art. Command languages, shells, macro systems, and text-injection patterns already exist; the brief is to mine them rather than invent from scratch.

“Do one single RCR, full frame … Confirm with me that you understand the structure of this prompt before moving ahead” — A bounded pass and a checkpoint: one deliberation over the complete context, and a read-back first — the same structural-confirmation move the operator uses when a prompt's shape matters as much as its content.

Reading the Operator's Shorthand

The prompt is written in the working vocabulary of the methodology. Here is what the shorthand means:

RCR
A structured, multi-round deliberation pass (Recursive Companion Review) where the board argues a design from several angles before anything is committed.
Full Frame
A deliberation setting where the board reasons over the complete context rather than a slice — nothing held back.
FBD
“Fail-By-Design” — the drive to build a process so that doing it wrong is harder than doing it right; “FBD away all problems” means design out the failure modes rather than patch them.
