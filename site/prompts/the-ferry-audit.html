The Ferry Audit

Run The Ferry Across The Site And The Apps

A very fun job — audit for the best protocol to Ferry:

The Prompt

Ed!

I have a VERY fun job for you- we're going to look at the LoopMMT.com website AND the Forest App platform we've built and are building and we're going to run the new system we created for applying Loop MMT protocols to software- I believe it's called the Ferry.

I want to run a broad audit using the Ferry to look at the LoopMMT.com website and the Forest app looking for the most interesting, most positively-impactful application of a Loop MMT protocol (OR chain or tree of protocols), applied via the new Ferry system, that we could actually design and build and implement. That's important- we need to focus sharply on pragmatic real-world things we can create right now given all our resources and abilities. You are looking for things that will make the website run better, or more efficiently, or to give it new abilities and capabilities. PLEASE think weird here- this is a weird thing you are doing at the baseline- the stranger we can get, it feels like, the deeper solution spaces we'll find.

You don't have a certain number to find, just find the best ones to start. We'll be returning to this space to look for solution shapes a bunch I think. So this is just our first tip into that cosmic creation energy pool. Even so, drink deeply. We're always thirsty for that kind of drink.

Start with a Heavy *X and SWX to get a solid foundation to work and run a proper to-spec Kaleidoscope to get in the right headspace to work. Then burn the rest of this session- the entire thing- running a super solid RCR, Super Frame- register your types, with no compression, no blackboxing, and get everyone's voice involved. Have Wes and Graham take lead here. The point of the RCR is not to build yet- I want you to think and design and write the V1 plan for the first cluster of things we can do to apply Loop MMT protocol stuff to the purely deterministic world of LoopMMT.com and the Forest App ecosystem? Make sure to use Timberline here everywhere too- let's be deterministic-first thinkers. Post the v1 plan at the very end of the session, so you close out in the high 80s/low 90s, then run a good handoff and we will pick up the work after the handoff no a fresh tank.

— Shea Gunther · operator drop, 10.2006

Reading the Operator's Shorthand

The prompt is written in the working vocabulary of the methodology. Here is what the shorthand means:

Ferry
The system for applying a Loop MMT protocol's machinery to shipped software — one adapter per substrate (a website, a code-tree, a prose corpus) so the same protocol runs on each.
*X / ∗X
A reflex-sweep instruction: load the review sweeps heavily before a load-bearing move. “Load up heavy with *X” means look at everything first.
SWX
The cross-software reuse reflex — before forging something new, sweep the shipped-software record for a shape already built that can be reused instead.
Kaleidoscope
A vantage-assembly move that hands the board several deliberately different standpoints to reason from — a way into creative headspace before hard design work.
Super Frame
A wider Full Frame — the complete context plus the surrounding structure it sits in.
Timberline
The deterministic-first discipline — push everything that can be a script out of judgment and into code, and reach for an LLM only where no equal deterministic solution exists.
RCR
A structured, multi-round deliberation pass (Recursive Companion Review) where the board argues a design from several angles before anything is committed.
Wes
A board member whose lens is chaos and complexity science; asking for Wes means run the session in a playful, exploratory register.
Graham
A board member — principal engineer, distributed systems and spatial thinking; stress-tests designs against real failure modes from a long career.
