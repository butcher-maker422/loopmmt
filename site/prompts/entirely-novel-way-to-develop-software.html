Come Up With An Entirely Novel Way To Develop Software

The Founding Mandate

An unbounded ambition, anchored to a single thing that could prove it wrong:

The Prompt

OK, here's our goal- come up with an entirely novel and new way to develop software in the AI agentic age. The broad idea is to take the conceptual model of the Loop 2.1 system and use it to create a way to structure both the development of software, using AI agents governed with managing a portfolio of in-context software, as well as the actual software itself, leaning into a model that looks to the Space Shuttle for fault tolerance and recoverability. It's re-thinking everything. Let's talk this through. The end product, the thing that will mark whether this is a success or failure, is a set of developed guidelines, rules, and files that I can use to develop an app for my father-in-laws deer butcher company in three days. The system we come up with, named the Loop MMT system, must allow me to develop first-class enterprise level software as a solo one man dev leading an AI coding assistant. So our job, again, is to come up with that system. Let's start by you looking over everything and hitting me up with a list of questions.

The Moment

Loop 2.1 had proven the operator could direct an AI to build something real. This prompt asked the harder question: could the way he had done it be turned into a system — a repeatable method that would let one person, leading an AI, ship enterprise-grade software alone. The prompt names that system in the act of commissioning it. It is the moment Loop MMT stopped being a way of working and became a thing with a name.

The mandate is enormous — re-think everything about how software is developed in the age of AI agents — and it is deliberately paired with a small, unglamorous, and completely falsifiable test: an app for the operator's father-in-law's deer butcher shop, built in three days. If the grand system could not produce the humble app on the deadline, the grand system had failed. That app became the Butcher Constellation, the methodology's first real project.

The wider frameAn unbounded ambition anchored to one shippable proof — the pattern that recurs across the whole system.

The Anatomy

"managing a portfolio of in-context software" — the framing treats software not as a single artifact under construction but as a portfolio the operator holds and rebalances, the way an investor manages positions. It is the seed of the methodology's whole stance toward the AI: not one big build, but many pieces held in view at once and governed deliberately.

"leaning into a model that looks to the Space Shuttle for fault tolerance and recoverability" — the reference is not decoration. It sets the engineering values up front: assume failure, design for graceful recovery, make the system able to lose a part and keep flying. That commitment to recoverability over cleverness runs straight through the methodology that followed.

"a set of developed guidelines, rules, and files that I can use to develop an app for my father-in-laws deer butcher company in three days" — the success criterion is concrete, dated, and owned by someone the operator cannot disappoint. It converts an open-ended research question into a shippable deadline. The typo stays because the prompt is real; the deadline stays because the whole method is built to meet exactly this kind of deadline.
