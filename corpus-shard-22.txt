The Glossary — real entries, in full

Real glossary entries, shown in full — 60 terms, each verbatim (definition, cross-references, and source line intact). This is the same glossary the Corpus page prints, folded from the same generator: one source, no hand-duplication. Selected by clearance, not edited to fit: 469 entries can be shown whole; this is a representative spread across them.

3P (Three Passes) DEV — A three-round iteration cycle for deliverable improvement: Build (produce V1), Repair (find and fix structural problems → V2), Reframe (step back, challenge the frame → V3). 3P is lighter than Self-Review and optimized for catching design limitations rather than defects. Pass 3 can be deferred across session boundaries. See also: Self-Review Protocol, The Forge

Advisory Board DEV — A fictional panel of named AI characters reconstructed from documents each session. Provides structured deliberation via RCR, design critique, and analytical diversity. Key members: Ed (permanent chair), Bev (silent note-taker), Graham, Nyx, Chen Wei, Dara, Renata, Margaux, Theo, Wes, Sol, Kira, Vee, Sable (operates the VERIDIAC), Leroy the cat, and Geoff (four-dimensional being — cannot be summoned). Board roleplay uses bold-name attribution. See also: RCR, Ice Breaker, Print Crew

Assign (Shuttle Modifier) DEV — A Shuttle routing modifier ( --assign <member>:{chair|cochair|owner}, repeatable) that binds named board member(s) to a role — distinct from > (route-to-member) and: (frame-bind). Preserves the role distinction (chair / co-chair / section-owner) and the group-chosen wrinkle: --assign group:chair lets the role-holder be selected by the board rather than named by the operator. Effect-type routing / role-binding; fidelity-zone @role. Built S04.1608 (Shuttle v1.8, the Tier-1 Five). See also: The Shuttle, Fidelity Zone, Express Pidgin

Ballast, The DEV — Filing debt triage system. Tiers items by cooperation impact: [C] critical (removal degrades cooperation infrastructure), [D] degrading (removal reduces quality over time), [X] cosmetic (removal has no cooperation impact). Includes TTL expiration and Red Queen substitution requirement. See also: cooperation efficiency threshold, Red Queen requirement. Source: Cooperation Architecture Item 5.

Block Taxonomy DEV — Rule 1 of the Block Principle. Name every element type in the system before specifying how they connect. Classification precedes composition — joints between unnamed elements cannot be specified. The taxonomy is the prerequisite: without it, the rest of the Block Principle has no substrate to operate on. See also: Block Principle, Joint Specification, Test by Removal

Bridge (Pattern) BOTH — A buffering mechanism between a loop's output and the bus. L21 analog: the PM bridge holds one ejected word until drained via bus. In MMT: smooths the flow when a loop produces output faster than the bus can carry it. Three overflow strategies: overwrite (latest wins), queue (FIFO), backpressure (loop pauses until bridge drains). Strategy and depth declared in the loop spec.

Calibration Drift MMT — The failure mode where a quality standard's thresholds drift relative to the population being measured, so that "passing" no longer means what it meant when the thresholds were set. Any standing quality instrument needs a periodic check against its own baseline. Also called The Meta-Prediction. Source: FWW(C)^FWW(C) domain, Panner throw 35.

Clamp (Pattern) BOTH — A Filter Loop that modifies specific fields within declared bounds. L21 analog: Threshold Gate clamp mode rewrites values to a configured bound without ejecting them. In MMT: bounds are declared in the Constellation Spec. onViolation: 'clamp' adjusts silently to nearest bound. onViolation: 'reject' treats as validation failure. Distinct from Compute Loops: a Clamp enforces bounds, not business logic.

Compensate MMT — One of five failure strategies. When a workflow step fails after earlier steps succeeded, the Workflow Loop executes compensation actions that undo the effects of previous steps. Each step can declare a compensate block in its pipeline spec — a packet to emit that reverses its effect. Based on the Saga pattern from distributed systems. See also: Abort, Skip, Escalate, Retry, Failure Vocabulary

Concurrency Strategy MMT — The declared policy for resolving simultaneous writes to the same record from different devices. Three options: last-write-wins (simplest — second write overwrites first), field-level merge (non-conflicting field changes both apply), optimistic locking (write fails if record version has changed since read). Declared per data type in the Constellation Spec. Both writes are always captured in the audit trail regardless of strategy.

Constellation Map MMT — A generated visualization of a constellation's structure produced from the Constellation Spec. Loops as nodes, buses as edges, routing entries as connections. A design-time comprehension tool — not a live traffic monitor. Answers: what are all the loops, how are they connected, what packet types flow between them, and where does a new module plug in? Because it is generated from the spec, it is always consistent with the spec and never hand-drawn from memory. As a constellation grows from 8 loops to 30 or more, the routing table becomes too long to hold in one's head as a list — the map makes the topology visible. Belongs alongside the Progress Dashboard and Action Plan as a planning and comprehension aid. Does not require the application to be running. Added in Standard v7. See also: Constellation Spec, Observatory, Progress Dashboard, Action Plan

Containment Moat MMT — The architectural property that prevents a failure in one loop from propagating to other loops. Enforced by two independent mechanisms: the closure wall (loops cannot access each other's internals) and bus contracts (loops cannot exchange non-conforming data). A failure in the Pricing Engine cannot crash the Order Vault.

Coordinator DEV — A dedicated, persistent AI conversation that manages the logistics of a Loop MMT development process. Maintains the event ledger, tracks module status, triages Integrator findings, surfaces decisions to the Operator, prepares routing manifests and loading packs. Runs from end of Phase 0 through project completion. Does not write code, verify code against the spec, or make architectural decisions. Manages flow (what goes where and when), while the Integrator manages correctness (does it satisfy the contracts). Can push back on the Operator when it detects conflicts; the Operator can always override, and the override is always recorded. See also: Event Ledger, Decision Queue, Routing Manifest, Auto-Routing, Integrator

Day Sheet DEV — A CMFP-derived inline mesh capturing a full day's work across all sessions. Five analytical positions mapping to independent dimensions: what happened (Chronology), what was made (Material), what was decided (Decisions), what's still owed (Debt), and where the project is heading (Trajectory). Fractal summarization: each scale compresses the one below it — session handoff → Day Sheet → future levels as needed. See also: CMFP, EOD, Context Mesh

Demand Loading DEV — Loading documents when the work requires them, not at session startup. The default file-loading strategy since FP v31 / Let's Go v1.4. Reduces startup context cost while preserving availability. Supersedes mandatory mesh loading. See also: Mill Mesh, Let's Go

Derive-Architecture DEV — A document form where operational controls are compiled into body sections rather than enumerated in a separate table. A Creed-aligned instance derives controls by reading the body — the document's structure IS the specification. Validated by the Chisel series. See also: The Chisel, FBD, The Creed

Draining Mode MMT — The third of three Dependency Gate modes. The dependency has recovered. The gate drains the local buffer in order at a controlled rate, confirming each write before sending the next. When the buffer is empty, the gate emits DEPENDENCY_ONLINE and returns to Live mode.

Event Ledger DEV — An append-only chronological record of everything that happens in a Loop MMT project. The source of truth. All other project documents — progress dashboard, decision log, session log, dependency graph — are materialized views derived from the ledger. Nothing is edited; corrections are new events. Each entry carries a sequential ID, timestamp, event type, session ID, payload, and a triggered-by reference tracing the causal chain. The Coordinator produces an updated ledger artifact after every event. The L21 analog is the session recording file — a replay log of everything that happened, from which any prior state is reachable. See also: Materialized View, Decision Log, Coordinator, Session ID, Ledger Compaction

FBD (Fix by Design) DEV — A design principle applied across Loop MMT architecture, code, and writing. Make failure modes structurally impossible rather than relying on behavioral compliance to avoid them. In architecture: the closure wall prevents a Compute Loop from accessing the database by never passing it the database client — the variable does not exist in scope. In code: coding standards enforce constraints that the test suite verifies mechanically. In writing: the FBD-W series defines structural writing constraints that eliminate specific prose failure modes. FBD shifts the cost of correctness from runtime vigilance to design-time structure. The first Creed drive. See also: FBD-W, Closure Wall, The Creed

Five Lenses DEV — The design scaffold evaluation framework. Five passes: Lens 1 (Audience + Purpose), Lens 2 (Structure), Lens 3 (Typography + Visual Hierarchy), Lens 4 (Departure Analysis), Lens 5 (Production Constraints). Followed by Grain Check. Domain scaffolds provide domain-specific guidance. See also: Design Scaffold, Open Scaffold, The Proof

Format Kernel DEV — The rendering engine layer of the design scaffold system. Base typographic and layout rules shared by all artifacts in a given medium. Medium specs are format kernels — how things render, not what to design. See also: Medium Spec, Skin, Design Scaffold

Full Knowledge Map DEV — A structured survey of all human knowledge organized into 12 domains, ~162 fields at L1, and subfields/topics at L2–L3. Used to derive corpus planning targets by identifying empty cells — making "what should we build next?" a reading exercise rather than a brainstorming exercise. Faceted at the structural level (Ranganathan over Dewey), enumerative at the top two levels where natural joints exist. Orthogonal to KP Architecture v1: the Architecture describes packaging (layers, lenses); the map describes content (what knowledge exists). Two operational tiers: L0–L1 (operational map, loadable) and L2+ (reference layer, per-domain). Nine structural mechanisms specified in the implementation plan (M1–M7 from Acid Bath, R1–R2 from Parallax). Permanent project resident. See also: Map Address, Operational Map, Reference Layer, Coverage Quality, Indicator Field, Scout Field, Negative Space (Map), Option Value (Knowledge), KP Architecture

grounding-state DEV — The claim-grounding register's per-claim status — not a claim's truth. A fact is a claim whose ground you checked and pinned (its certificate = the input hashes); an assumption is a claim whose ground you deferred; a decision is a claim whose ground is its premises. One claim can move between states along one seam: assume ─discharge→ verified ─(an input moves)→ STALE ─(re-derive)→ verified — so STALE is a fact fallen back to assumption-status. verify reads the grounding-state (FRESH/STALE/DEAD/ASSUMED); it never re-judges truth ( ⊢, not ⊨). See also: The Claim-Grounding Register, the discharge edge, the decision cell, unexpired ≠ true

Hydration (Pattern) BOTH — A Filter Loop that receives a sparse packet (just an ID), pulls full data from a Vault, and attaches it before passing the enriched packet along. L21 analog: loading a value from memory into the ALU loop to enrich the workspace before computation. Always done by a Filter Loop (enriches, not transforms); the pull goes through the Vault Bus. Downstream loops get everything they need in one packet.

Integrator DEV — A persistent AI conversation that manages correctness in a Loop MMT development process. Holds the full Constellation Spec, contract registry, and routing table. Verifies deliverables from module conversations against the spec and produces tagged verification reports — each finding carries a category (mechanical, judgment, architectural) and confidence level (high, low) that the Coordinator uses for routing. Maintains its own verification log independent of the Coordinator's event ledger. Does not write code, track project status, or make architectural decisions. See also: Finding, Coordinator, Verification Gantry

KX (KP-load / production-time Pull) DEV — An operator command. After task comprehension and before production, provisions knowledge packs for requisite variety: clone the library repo if absent, load relevant domain packs (math, science, design, human-PoV, and others the task footprint implies), plus two probes — the Wildcard (one random pack, two-glob draw) and the Foil (one pack predicted useless, loaded with its reason). The production-side mirror of The Pull (Self-Review v11 §1c), kin to FBD-PF7. Each pack carries a one-line reason; pack count never anchors output scope (Goodhart brake). Canary-scaled: full GREEN, reduced YELLOW, suspended RED. As of Shuttle v1.8 (S04.1608) KX is in the canonical Shuttle command table ( KX --domains {<list>|auto}, provisioning / @equipment), closing F4 with EXEC. See also: The Pull, FBD-PF7, EXEC, AX, BX, The Shuttle, Fidelity Zone, Wildcard, Foil, Express Pidgin

Let's Go DEV — The session opening protocol. Current version: v1.14. Governs the sequence from the operator's first message to the first substantive response: mount check, weather vane, byte-truth floor open, Champollion, ice breaker, demand-loaded files. Every conversation is a session — the open runs on every first message (FP §6 / Amendment S06.0751); a bare signal ( LG! / Ed!) takes the full sequence, a directive or substantive question takes the hybrid path (open, then act/answer). See also: Ice Breaker, Demand Loading, Open Card, Hybrid Path

Loop Recovery Protocol MMT — The four-step mandatory protocol when any individual loop encounters an error: (1) Do not crash — catch the error. (2) Alert the bus — emit LOOP_ERROR. (3) Preserve state — do not modify state after an error. (4) Continue operating — return to ready state for the next message.

Medium Spec DEV — A format-specific rendering specification: type scale, grid, spacing, page geometry, color constraints, fidelity rules. Examples: Medium Letter BW, Medium Screen, L21. A stylesheet, not a design system — rendering is downstream of design. Must include an FWW(C) Vocabulary section. See also: Format Kernel, Skin, FWW(C) Vocabulary

Mill Mesh DEV — The collective term for the five Mill context documents loaded at session open: Place Document, Operational Weather, Computational Architecture, Wear Ledger, and Framing Pack. Compressed to v2-rc (~12.2K tokens total) via The Pare. Loaded on demand per Let's Go v1.4. The Mill's fictional world as reconstruction infrastructure. See also: The Pare, Demand Loading, The Mill

Open Scaffold DEV — The fallback design path for artifacts with a design surface but no domain module match. Five Lenses without domain-specific guidance. Used for unscaffolded artifact types or cross-domain artifacts. See also: Five Lenses, Design Scaffold

Outbox (Pattern) MMT — A persistence buffer that holds outbound messages until confirmed delivered to an external service. When a Signal Loop needs to send an email, SMS, or webhook, it writes the message to the Outbox Vault first, then attempts delivery. If delivery succeeds, the record is marked sent. If the process crashes after writing but before delivery, the message is retried on recovery. Prevents silent message loss without requiring distributed transaction coordination. Pairs with the Dead Letter pattern for messages that exhaust all retry attempts. See also: Dead Letter (Pattern), Signal Loop, Retry

Patterns Reference DEV — A companion document to the Standard that catalogs implementation patterns — useful techniques for working within the Loop MMT architecture that do not constrain constellation design. The full catalog of twenty-one implementation patterns: Flag, Scratch, Clamp, Stamp, Reorder, Counter, Fanout, Debounce, Split-Merge, Cascade Update, Sentinel, Heartbeat Absence, Replay, Inlet, Document Generation, Self-Routing Packets, Phantom, Tap, Inter-Constellation Communication, Dead Letter, Outbox, Snapshot. The Standard defines architectural patterns (patterns you must know to design correctly). The Patterns Reference defines idioms operators learn over time. The document contains thirty patterns total: nine architectural and twenty-one implementation. See also: Standard

Preflight DEV — The mount-check and state-load sequence at session start. Ten controls across three tiers: Essential (every session), Periodic (state > 48hrs old), Production (per substantive task). Fail-loud. Mount failure = hard stop. See also: Canary, Field Manual

Pull (Request) MMT — One of two bus communication modes. A loop requests a capability by type, not by target. The bus consults the routing table, determines which loop handles that request type, routes the request, and returns the response. The requesting loop is decoupled from the provider. See also: Push, Type-Routed Pull

Recipes / The Recipes DEV — The general pattern (genus): published, human-readable documentary prose about how to compose a thing — loose enough to trust the reader, meant to be read and shared and at most referenced during development. The load-bearing structural fact (operator Pastry, S14.2337) is that a Recipe is documentary, not functional: like a real-world cooking recipe (ingredients + steps, not an exhaustive wiring diagram), nothing consumes a Recipe — it is not fed to any machine. This is the human-facing sibling of the Schematic (the machine-fed exact wiring a Compiler ingests): same subject, opposite consumer. A Recipe is domain-neutral — it could be a composition of Gifts, or literally a recipe for baking a cake; instances are touched as needed. The species (loopmmt.com): the first-class Recipes collection (peer to Sweet Prompts and Gifts) — each Recipe snaps several Gifts into one working thing, start to finish, so a reader argues with the assembly instead of the pitch. Two-axis tagged (domain + register: workaday/clever/wild); reuses the Sweet Prompts spine. Live trap: Gifts are the palette, not a grammar to enforce. See also: Schematic, The Compiler, Gifts, Sweet Prompts

Reorder (Pattern) BOTH — Cascade filter order is a routing concern, not a filter concern. L21 analog: the operator can switch whether Pattern Matchers run before Threshold Gates. In MMT: want authorization before validation? Change the routing table. Want to insert a new step? Update the routing. The filters themselves don't change. Only the routing table does.

Root ARCH — One of three tool levels in the Tree Catalog. Root tools are invisible infrastructure — plumbing that serves every tree but belongs to none. The customer never interacts with them directly. 11 Root tools: Vault, Stamp, Canary, Fence, Notary, Archive, Dock, Ring, Sieve, Mirror, Auth. All BUILT. See also: Trunk, Branch, Tree Catalog, Tree

Schulz Test DEV — A derived property verification for the Block Principle: can you identify the block types in a finished artifact by visual inspection alone? Named for the clear, simple visual grammar in Peanuts comic strips — panel, character, punchline are always identifiable. If block boundaries are invisible to a reader, container opacity may be too high or the taxonomy is under-specified. A passing Schulz Test means the structure is legible. See also: Block Principle, Container Opacity, Container Boundary Comments

Semantic Boot Order MMT — The principle that some components must exist for other components to mean anything — not just to function, but to have semantic content. Distinct from implementation dependency (what calls what). Semantic dependency: what gives meaning to what. Named from tide pool keystone species ecology. Source: Tide pools / Geoff, Panner throw 34.

Signal Bus MMT — One of the named buses. Carries outbound notifications, audit events, and external service calls. Isolated because external services are the most likely failure point. A Signal Bus failure does not affect the Data Bus or Vault Bus.

Sober Witness DEV — A board member who opts out of one or more steep components and therefore observes the altered room from an unaltered (or less-altered) vantage point. Sober witnesses are not sidelined — their sobriety is load-bearing. The collision between altered and unaltered perspectives is where the analytical value lives. In crosses, a character who opts out of every component steep is fully sober. Nyx is the most common sober witness (declines all substances except caffeine). The Study Stack is the only cross with no sober witnesses — every board member is altered. See also: The Steep, Cross (Steep)

STEP Line DEV — The handoff-header line that records a session's Stepping Variable and lap outcome. Format: [STEP: <variable> | status: advanced/held/fuzzy/none | next: <proposed next variable>] (with also: listing the other variables when fuzzy). Adjacent to the [REP] line. Written once per handoff in exactly this format so grep '\[STEP:' eod-handoff-.md reconstructs the complete experiment log and proposed-next chain without parsing prose. The next: field is the source of record for the immediate-next stepping variable (Reconciliation A); session-state "What's Next" #1 renders it. Presence and well-formedness are checked in the Handoff Pulse Line completeness check. See also: Stepping Variable, Handoff Standard, REP Line*

Super RCR DEV — Three-round structured critique. Round 1 (Encounter): independent positions. Round 2 (Dialogue): cross-talk and challenges. Round 3 (Integration): dual-focus synthesis. Distinct from 3P (iterates own deliverable) and Board Report (no cross-talk). See also: RCR, 3P

Tenant Scoping Pattern MMT — A noted future extension from Standard v7. Data-layer tenant isolation for multi-tenant constellations. Logic-layer controls are already specified: the Auth Gate stamps packets with tenantId, scoped subscriptions filter delivery by tenant, and RBAC predicates enforce record-level access. What is not yet formalized is how tenant isolation is enforced at the storage layer — ensuring Tenant A's records are physically or logically separated from Tenant B's in the database. For Postgres-based constellations, the mechanisms are well-understood (Row Level Security policies, schema-per-tenant, separate databases). Because all database access is concentrated in Vault Loops, a formal tenant scoping pattern would affect exactly one loop type. Will be specified when a real multi-tenant project requires it. See also: Auth Gate, Scoped Subscription, Vault Loop, Role-Permission Matrix

The Bequest MMT — In the Projects-System, the minimal Charter residue: a field belongs to a project's Charter only if it cannot be recomputed from the rest of byte-truth (the repo excluding the Charter). Everything with conditional entropy zero against that rest is render, not Charter — so the Bequest is exactly what the successor cannot derive and must be told. The decidable test ("can the successor recompute this? if yes, it does not belong") is the whole discipline. See also: Charter, the Projects-System, The Headwaters.

The Clink DEV — Session completion ritual. Each board member delivers one honest sentence about what mattered in the session; Shea pins a favorite line. Marks the distinction between productive closure and mere stopping. Not every session ends with a Clink — it fires when substantive work ships. Sol facilitates. See also: Advisory Board, Trophy Case

The Count Line DEV — loopmmt.com's derived-count drift instrument: binds each on-page count-claim (prose stating a NUMBER about other on-page content — "in nineteen words", "seven things built") to a decidable byte-oracle and CHECKS (exit 3 on drift) or STAMPS (computes the truth from the page's own bytes and writes it, idempotent). Strictly stronger than the check-only Canon Line: a count is decidable where a sentence-paraphrase is not, so the oracle IS the counted content — no second copy of the truth exists to drift. A count-canonical.json registry binds each claim to oracle · surfaces · render; every oracle is a pure function of committed bytes (safe to re-run in the deploy BUILD). Wired fail-closed into predeploy_gate.sh; determinism win seq=525. Sibling of the Canon Line + the Altitude Parity gate (the site single-source check/stamp family); a station-3/4 member built inside The Capstan's first turn. Honest ceiling: it trues a numeral it can FIND via the claim's regex — not a count stated in prose no pattern anticipates ("a handful of apps"); visibility, not immunity. projects/loopmmt-website/count_line.py. Built S22.1203. See also: The Canon Line, The Altitude Parity, The Capstan, The Making, the-determinism-register.

The Fblthp MMT — A quarantine protocol for unclassifiable input. When a classification system encounters input it cannot categorize, the correct response is quarantine with a feature manifest — not rejection. Named for the perpetually lost homunculus from Magic: The Gathering. The Fblthp is not garbage. It's input the system hasn't learned to see yet. If the same unclassifiable pattern recurs, that's a signal to build it a home. Source: Hearst × MTG domain, Panner throw 38.

The Gold Wash Convention DEV — Named system property: the living, uniqueness-gated register; the Wobble Convention one structural level up. Mines the gold corpus (every Panner / Acid Bath finding) for unique invariants and lands them in The Lode — a derived, append-only register superseding the static Ultimate Gold Report. Four generating functions: WASH (the run), GATE (the load-side uniqueness filter / Prior-Art Gate wired onto gold), SETTLE (the fold, rides the Nightly Settle), ASSAY (re-wash the refined stock) — plus CAST (synthesis, specced). Built S04.1223; carrier seated S04.1322. See also: The Lode, Strike Log, find: event, The View Test, CAST, The Wobble Convention, The Panner, The Acid Bath, Prior-Art Gate, Growth-Ring Convention, GX

The List DEV — Sable's (and any evidence-only member's) failure-trajectory warning channel, governed by The List Convention v1. A low-authority, evidence-shaped flag: [LIST: <axis> | <slight|clear|steep> toward <failure mode> | basis: <tabled readings>]. Grounded in the annunciation principle (alarm design): it reports the condition and names the trajectory but never the remedy (the LIST-K1 firewall — the moment it suggests a fix it becomes a directive and breaks). The subject is always the readings, never the member; it obligates nothing and is logged always; open [LIST] s reconcile at close (righted/held/realized) and earn standing by calibration, not assertion. Built S31.0857; first fired on the session's own context budget. See also: The List Convention, No Directives Rule, Annunciation, Sable, The Canary

The Pennant DEV — The WO naming & dispatch standard (Core Document v1, S01.0703). Encodes the operator's four signals in the WO name: venue, model tier, and run topology. Handle WO-<ROUND>[<member>]-<TIER><VENUE>; canonical ID adds date and slug. Round = topological level in the merge DAG (hand-readable and machine-derived — reconciles "the name tells me the order" with "order is derived, never typed"); member = parallel slot. Realizes the Yard v2 "Name" lifecycle stage (§4). Designed by parallax (4 beams), self-reviewed (the Pull — SHIP). Named for the naval signal pennant: type letters and a hull number. See also: Lane (Pennant), Round (Pennant), Member (Pennant), Hull (Pennant), The Yard

The Reversal Check MMT — A mid-chain quality gate that prevents wasted work. In multi-step production, insert lightweight quality assertions between stages. If an assertion fails, stop before investing further resources in a doomed pipeline. Named from competitive eating: if a competitor reverses, all preceding consumption is retrospectively invalidated. Source: Competitive eating domain, Panner throw 32.

The Stitch DEV — Protocol integration assessment. Three phases: X-Ray (structural analysis), Overlay (map interfaces), Yield (net simplification). A composition detector — finds where a new protocol's interface matches an existing surface. Must not increase complexity. See also: Simplicity Yield, PiF

The Vanishing Ball DEV — The Super RCR (S05) that proved the Constraint drive geometrically. The volume of the unit n-ball, V(n)=π^(n/2)/(n/2)!, rises to a crest near n\ ≈5.26 and then falls toward zero as more dimensions are added — capability is not monotonic in dimension, so past the crest, adding makes the system worse. Registered nball in The Math in Force as its first LOAD-BEARING result. The operator's framing is kept verbatim: "we walked backwards into it, but that does not mean we're still not held up by the equation" — the discipline was built first and the theorem found beneath it; the order of discovery does not change what holds the building up. See also: The Math in Force (MiF), the reckoner, The Creed*

thermostat DEV — Pre-kill diagnostic in the Astrolabe program. At build 5 of instrumented builds: is anyone reading the instrument data? If no one is reading posterior reports or using Rosetta rows, diagnose the measurement system before proceeding. Precedes the AND kill switch at build 10. Established S~158 (Nyx + Renata convergence).

Translator (Pattern) MMT — The data-scrubbing half of a loop that adopts an external dependency speaking a foreign data model — a payment processor webhook format, a legacy SOAP API, an OIDC provider's token structure. The Translator receives raw external data, validates it against the external provider's schema, maps it to the internal packet contract, and emits clean packets indistinguishable from any other packet on the bus. The translation logic is isolated inside the loop's closure — no other loop knows or cares that the data originated externally. The Translator formalizes two distinct responsibilities that share the same loop: the Translator handles what happens when the external system responds; the Dependency Gate handles what happens when it is unreachable. Both should be declared in the Constellation Spec, making the data-scrubbing responsibility a design-time decision visible in the spec rather than an implementation detail discovered during coding. Added in Standard v7. See also: Dependency Gate, Adopted Dependency, Packet Contract Registry, Filter Loop

Trunk ARCH — One of three tool levels in the Tree Catalog. Trunk tools are shared resources that appear across multiple trees. Each has a primary tree (where it anchors or has its strongest role) and secondary trees (where it serves as a member). 15 Trunk tools: Contact, CMS, Calendar, Pulse, Flare, Analytics, Tome, Commerce, Scheduling, Forms, Email, Compliance, Tracker, Bridge, Sync. See also: Root, Branch, Tree Catalog, Tree

VERIDIAC MMT — The deterministic verify-co-processor the board reaches for when it needs a result computed and verified, not decided. The machine Sable operates (the person ≠ the machine). 13-verb ISA, the Result Envelope, the Tape, the Bit-Correctness Floor. Does not steep. Formerly "the Sable Terminal" (V1–V3).
