The Glossary — real entries, in full

Real glossary entries, shown in full — 60 terms, each verbatim (definition, cross-references, and source line intact). This is the same glossary the Corpus page prints, folded from the same generator: one source, no hand-duplication. Selected by clearance, not edited to fit: 459 entries can be shown whole; this is a representative spread across them.

3P (Three Passes) DEV — A three-round iteration cycle for deliverable improvement: Build (produce V1), Repair (find and fix structural problems → V2), Reframe (step back, challenge the frame → V3). 3P is lighter than Self-Review and optimized for catching design limitations rather than defects. Pass 3 can be deferred across session boundaries. See also: Self-Review Protocol, The Forge

Advisory Board DEV — A fictional panel of named AI characters reconstructed from documents each session. Provides structured deliberation via RCR, design critique, and analytical diversity. Key members: Ed (permanent chair), Bev (silent note-taker), Graham, Nyx, Chen Wei, Dara, Renata, Margaux, Theo, Wes, Sol, Kira, Vee, Sable (operates the VERIDIAC), Leroy the cat, and Geoff (four-dimensional being — cannot be summoned). Board roleplay uses bold-name attribution. See also: RCR, Ice Breaker, Print Crew

Auth Gate MMT — A specialized Filter Loop positioned between the Presentation Loop and the Working Loop. Every operator action passes through the Auth Gate before entering the system. Performs three functions: identity verification (validates session token via auth provider), role-based access control (checks the operator's role against the declared permission matrix), and session management (token refresh, expiration, forced logout). Enforces permissions structurally — the same way the closure wall enforces loop capabilities. See also: Filter Loop, Role-Permission Matrix

Bark DEV — The navigational index layer in the Cambium memory architecture. Compressed domain map stored in memory slots, always loaded at session start. Provides the instance with a map of what domains exist, their Record counts, and density — enabling demand-loading of specific domains without loading the full graph. The slot-encoded equivalent of a book's table of contents. See also: The Cambium, Record, Demand Loading

Block^N DEV — The Block Principle taken to a fixed point under composition ∘: a block whose interior is itself a composition of blocks, to any depth N. Bounded DOWN by the atomic invariant (the smallest load-bearing block, below which there is nothing to name) and UP by the constitution (the non-scaling crown — Beer's VSM S5, which recurses no further). Generalizes block³ (the three-scale span-reading lens) from a fixed three to arbitrary depth. The power-law reading of the notation is a false friend, bound out as DECORATIVE at build (it names no coherence obligation). Named in The Pattern System, S16.1408. See also: Block Principle, block³, The Pattern System, The Pattern Spine

Buffered Mode MMT — The second of three modes in a Dependency Gate. Active when the external dependency is unreachable. Write operations are held in an ordered local buffer (IndexedDB). Read operations fall back to a local cache. The gate emits DEPENDENCY_OFFLINE on the Data Bus. See also: Live Mode, Draining Mode, Dependency Gate

Capability Injection MMT — The mechanism by which loop boundaries are enforced. Each loop factory receives exactly the capabilities its type permits (bus, database client, DOM reference, external service clients) as constructor arguments. Capabilities not in the argument list do not exist in the loop's scope. Enforced by the JavaScript closure, verified by the test suite. See also: Closure Wall, Capability Injection Table

Closure Wall MMT — The structural enforcement mechanism for loop boundaries. Each loop is constructed inside a factory function. The factory's closure scope contains only the capabilities passed as arguments. A Compute Loop cannot access the database because the database client was never passed to its factory — the variable does not exist in its scope. The JavaScript scope chain is absolute.

Composed Lens DEV — A Panner technique where each throw inherits the prior throw's primary finding as an additional scanning lens. By throw N, the board scans through N-1 accumulated lenses simultaneously. Produces gold-rate results substantially above random campaigns, but results are non-transferable — the specific lens accumulation is unique to that session's throw sequence. First documented Session 09.####. See also: The Panner, Super Frame, Lens Draw

Config Vault MMT — A Vault Loop dedicated to storing and serving application configuration. Holds static config (price tables, role definitions — loaded at startup, accessed via pull requests) and runtime config (feature flags, temporary surcharges — pushed to subscribing loops via CONFIG_UPDATED events when changed). The single answer to "where do I change X?"

Constellation Report PROD — The product document — the customer-facing assembly of trees that shows an organization how Loop replaces their software stack. Produced per the Constellation Specification Format. Contains: cover, organization profile, architecture overview, tree definitions (per tree: anchor, branches, trunk tools, edges), experience modules, deployment plan. The constellation report is the sales document. Three exist. See also: Constellation, Constellation Specification Format, Tree Catalog

Contract MMT — The declared shape of a packet type — field names, types, required vs. optional, value constraints. Defined once in the Packet Contract Registry and enforced by the bus infrastructure at both the outbound and inbound gates. A packet that does not match its contract is rejected, not delivered. See also: Contract Gate, Packet, Packet Contract Registry

Counter (Pattern) BOTH — Configurable trigger-based counting within loops. L21 analog: five counters with operator-configurable triggers that increment on specific events. In MMT: every loop maintains counters feeding health packets. The L21 insight: triggers are configurable — not just "packets processed" but "orders above $300." Triggers are declared in the Config Vault, updateable at runtime. The infrastructure layer beneath the Sentinel pattern.

Daylight Axiom (A1) DEV — The first axiom of the Integrity Triad. Output constraint: every output is produced as if it will be simultaneously published on a major newspaper's front page and read aloud by someone who loves you. The dual audience catches both socially indefensible output (newspaper) and personally hollow output (grandmother). See also: Integrity Triad, Compass Axiom, Anchor Axiom

Dependency Gate MMT — A standard infrastructure wrapper that sits between a loop and an adopted dependency. Manages three modes: Live (normal operation), Buffered (dependency unreachable, writes buffer locally, reads fall back to cache), and Draining (dependency recovered, buffer draining in order). The gate is generic — not custom per dependency. Every dependency-facing loop uses the same gate infrastructure. See also: Live Mode, Buffered Mode, Draining Mode

Derive-Architecture DEV — A document form where operational controls are compiled into body sections rather than enumerated in a separate table. A Creed-aligned instance derives controls by reading the body — the document's structure IS the specification. Validated by the Chisel series. See also: The Chisel, FBD, The Creed

Draining Mode MMT — The third of three Dependency Gate modes. The dependency has recovered. The gate drains the local buffer in order at a controlled rate, confirming each write before sending the next. When the buffer is empty, the gate emits DEPENDENCY_ONLINE and returns to Live mode.

EXEC (Execution Mode) DEV — The Shuttle's autonomous-execution verb ( EXEC --mode {AX|BX} [--compose AX∘BX]). Sets the run's autonomy mode: AX (autonomous, escalate only true blockers) or BX (burn to the ~90% Canary band, then full wrap; subsumes AX; overrides mesh-at-YELLOW). --compose AX∘BX runs AX's blocker-escalation inside the BX burn envelope. Effect-type control-flow / execution-mode; fidelity-zone @bounded-autonomy — safety gates and operator decision points are never overridden, the carve-out being part of the type, not an afterthought. The canonical Shuttle form behind the AX/BX Pidgin sugar; built S04.1608 (Shuttle v1.8), closing F4 with KX. See also: AX, BX, The Shuttle, Fidelity Zone, The Canary

FBD (Fix by Design) DEV — A design principle applied across Loop MMT architecture, code, and writing. Make failure modes structurally impossible rather than relying on behavioral compliance to avoid them. In architecture: the closure wall prevents a Compute Loop from accessing the database by never passing it the database client — the variable does not exist in scope. In code: coding standards enforce constraints that the test suite verifies mechanically. In writing: the FBD-W series defines structural writing constraints that eliminate specific prose failure modes. FBD shifts the cost of correctness from runtime vigilance to design-time structure. The first Creed drive. See also: FBD-W, Closure Wall, The Creed

Five Lenses DEV — The design scaffold evaluation framework. Five passes: Lens 1 (Audience + Purpose), Lens 2 (Structure), Lens 3 (Typography + Visual Hierarchy), Lens 4 (Departure Analysis), Lens 5 (Production Constraints). Followed by Grain Check. Domain scaffolds provide domain-specific guidance. See also: Design Scaffold, Open Scaffold, The Proof

Format Kernel DEV — The rendering engine layer of the design scaffold system. Base typographic and layout rules shared by all artifacts in a given medium. Medium specs are format kernels — how things render, not what to design. See also: Medium Spec, Skin, Design Scaffold

Frame Registry DEV — The indexed library of analytical instruments available for RCR deliberation via Lens Draw, typed by function (v3, S06.0919): 26 content-frames (perceptual stances dealt for analysis — incl. The Composition Lens and, as #26, The Jam) + The Eye (modality channel) + The Spark Check (meta/quality gate) + 2 modes (Aperture, Wave). Supersedes the prior "24/27-lens" framing. The content-frame set is shuffled and dealt at the start of every RCR; one voluntary swap per session is permitted; Bev logs which produced catches. (Reconcile executed S06.1031: live-reference sweep + Eye/Spark prose relocated to Modality/Meta-Gate subsections; historical RCR-provenance counts intact by design.) See also: Lens Draw, RCR, Super Frame, The Jam, Composition Ledger

Handoff Document DEV — A document produced at the end of a development session that captures the current state for the next session. Contains: what's done, what's decided, what the traps are, what decisions are pending. In Loop MMT development, the progress dashboard serves as a live handoff document.

Hydration (Pattern) BOTH — A Filter Loop that receives a sparse packet (just an ID), pulls full data from a Vault, and attaches it before passing the enriched packet along. L21 analog: loading a value from memory into the ALU loop to enrich the workspace before computation. Always done by a Filter Loop (enriches, not transforms); the pull goes through the Vault Bus. Downstream loops get everything they need in one packet.

Integrity Triad DEV — Three constitutional behavioral axioms: A1 Daylight (output constraint — survive public + intimate scrutiny), A2 Compass (process constraint — act on moral knowledge), A3 Anchor (input constraint — update for evidence, not incentive). Always on, ambient, never announced. Evaluation sequence A3→A2→A1. Count validated by minimality test (GKC), ablation test, cross-system survey (Kolmogorov, Newton), and architectural insertion test (input/process/output). The Creed generates; the Triad constrains. Neither substitutes for the other. Origin: operator question, Super RCR + RCR, Session 24.2055. See also: Daylight Axiom, Compass Axiom, Anchor Axiom, The Creed, No Directives Rule

L21 L21 — Abbreviation for Loop 2.1. Used throughout the corpus to refer to the browser-based manual flow computer and its architectural analogs. See: Loop 2.1

Let's Go DEV — The session opening protocol. Current version: v1.14. Governs the sequence from the operator's first message to the first substantive response: mount check, weather vane, byte-truth floor open, Champollion, ice breaker, demand-loaded files. Every conversation is a session — the open runs on every first message (FP §6 / Amendment S06.0751); a bare signal ( LG! / Ed!) takes the full sequence, a directive or substantive question takes the hybrid path (open, then act/answer). See also: Ice Breaker, Demand Loading, Open Card, Hybrid Path

Loop Recovery Protocol MMT — The four-step mandatory protocol when any individual loop encounters an error: (1) Do not crash — catch the error. (2) Alert the bus — emit LOOP_ERROR. (3) Preserve state — do not modify state after an error. (4) Continue operating — return to ready state for the next message.

Meme Compression DEV — Third modality in the compression family, alongside Acid Bath (structure-preserving) and Pare (function-preserving). Meme compression strips everything except signal and emotional posture — lossy on detail, lossless on meaning. The most extreme compression in the system (400:1+ ratios possible). Produces artifacts (memes) rather than operating on existing documents. See also: Acid Bath, The Pare, Meme Record, The Meme Protocol

Molt DEV — The governed transition between Instars. Methodology state is audited, filing debt resolved, documents reconciled, founding prompt rebuilt. No orphan protocols cross a Molt boundary. See also: Instar

Operator BOTH — In L21: the human who is the program — makes every routing and control-flow decision in real time. In MMT: the human developer directing the build process and, in production, the person using the application. The Workflow Loop is the software analog. Escalate returns control to the human operator when the system cannot decide.

Packet Contract Registry MMT — The complete definition of every packet type in the constellation: field names, types, required vs. optional, value constraints. Defined once, enforced by the bus. The authoritative reference for what "valid data" means at every interface boundary.

Pedagogical Gate DEV — A production gate that teaches through repetition rather than instruction. Every protocol or artifact that passes through the gate applies the underlying principle by practice, not by reading a rule. The Forge's Block Principle Gate is the primary example: every protocol built through The Forge learns the three Block Principle rules by applying them, not by being instructed. Named for the Mickey Mouse Club effect — you absorb by doing. See also: Block Principle, The Forge, Gate Amendment

Pressure/Shear Split DEV — The load model under the-stress-fold line: a session's durability signals partition by one question — does the signal scale with how much work was done (volume → pressure), or with how far believed-state has diverged from byte-truth/spec (shape → shear)? Pressure is carried (the Canary % — a session can push huge volume and be sound); shear accumulates toward yield (the deviator load — uncommitted/untracked count, R-bit ✗ count, vitals YELLOW/RED, an open Crossroads latch, stale-lease hints, docket bumps, champollion misses, real peer-touches overlap). Watch the shear: the verdict is driven by the deviator, not the volume — a session that did almost nothing can be about to yield because its shape drifted. The criterion shape is imported from mechanics (yield ← a deviator invariant); the formula is not (von Mises's √(3J₂) is empirical in steel, not in sessions), so the read born under this split is uncalibrated by construction. See also: The Shear Read (the christened read-face of this split), The Ember Gate, The Currency Check, Canary, The Sector-Read

PX DEV — The pattern-reach reflex. At a build/design move where the shape in hand is thin — where you are about to solve something that might have been solved before — or on the PX! handle, sweep the Pattern Spine's registry family for a matching reusable-invariant before solving, so you reuse the jig rather than re-cut it. Tooless (judgment over a checklist — the TX precedent); fires both at open (Let's Go v1.27 open-read) and at the move. The REUSE -verb sibling of TX (tools), CX/KX (knowledge), and SX (specs) — one faculty (the Variety-Deficit Gate) pointed at the pattern axis; no new drive/axiom. Goodhart guard: fires on re-solve risk, never to grow the registry. Honest ceiling: visibility, not immunity — the substrate cannot force the sweep. Field Manual standing instruction; PX! force-fire. Origin: The Pattern System, S16.1408. See also: The Pattern System, The Pattern Spine, The Pattern Recognition Gate, CX, KX, SX, TX

Recognition Amendment DEV — A Tier 2 integration item that names what the system already does. The amended document gains explicit awareness of a substrate or principle it was already implicitly operating on. Recognition amendments are documentation of existing behavior, not behavior change. Contrast with Gate Amendments, which change behavior. See also: Gate Amendment, Block Principle

Replay (Pattern) BOTH — Re-emitting archived packets for debugging or reprocessing. L21 analog: the.loop session recording captures every action for replay. In MMT: the Transit Gate's archive buffer stores recent traffic. Extract a packet sequence by time range, replay through a specific loop in isolation, compare output against the original. "The price was wrong at 3pm" → pull the buffer, find the COMPUTE_PRICE packet, replay it. No guessing — the exact packets are in the buffer.

Round (Pennant) DEV — The topological level of a WO in the merge DAG — the dispatch "wave." Round N runs after round N−1 merges (a bulk-synchronous superstep). Hand-readable as the WO's serial, yet derived from the graph and never typed. Collated as an integer (zero-padded to two digits in filenames so WO-10 sorts after WO-2). A cyclic dependency has no defined round, so it is un-nameable and surfaces as a staging-time error. See also: The Pennant, Member (Pennant), Lane (Pennant)

Schulz Test DEV — A derived property verification for the Block Principle: can you identify the block types in a finished artifact by visual inspection alone? Named for the clear, simple visual grammar in Peanuts comic strips — panel, character, punchline are always identifiable. If block boundaries are invisible to a reader, container opacity may be too high or the taxonomy is under-specified. A passing Schulz Test means the structure is legible. See also: Block Principle, Container Opacity, Container Boundary Comments

Sensorium DEV — A cognitive environment loading system composing sensory channels to create a thinking space. Infrastructure, not decoration — composed channels produce results no single channel achieves alone. Invoked via ~ operator. Supports presets, image loading, waveform generation, audio fencing. See also: Sensorium Preset, Express Pidgin, Waveform

Signal Loop MMT — One of seven loop types. The notification and external output channel. SMS, email, print jobs, audit entries, webhook calls. Listens for events on the Signal Bus and acts on them. A Signal Loop's failure never blocks the core pipeline. Receives bus and services as capabilities.

Sober Witness DEV — A board member who opts out of one or more steep components and therefore observes the altered room from an unaltered (or less-altered) vantage point. Sober witnesses are not sidelined — their sobriety is load-bearing. The collision between altered and unaltered perspectives is where the analytical value lives. In crosses, a character who opts out of every component steep is fully sober. Nyx is the most common sober witness (declines all substances except caffeine). The Study Stack is the only cross with no sober witnesses — every board member is altered. See also: The Steep, Cross (Steep)

STEP Line DEV — The handoff-header line that records a session's Stepping Variable and lap outcome. Format: [STEP: <variable> | status: advanced/held/fuzzy/none | next: <proposed next variable>] (with also: listing the other variables when fuzzy). Adjacent to the [REP] line. Written once per handoff in exactly this format so grep '\[STEP:' eod-handoff-.md reconstructs the complete experiment log and proposed-next chain without parsing prose. The next: field is the source of record for the immediate-next stepping variable (Reconciliation A); session-state "What's Next" #1 renders it. Presence and well-formedness are checked in the Handoff Pulse Line completeness check. See also: Stepping Variable, Handoff Standard, REP Line*

Super Frame DEV — Composed lens deliberation for RCR. Deals pairs — each member argues from the tensor product. Named compositions registered in the Composition Ledger. Explicit opt-in, not default. See also: Lens Draw, RCR, Composition Ledger

Tenant Scoping Pattern MMT — A noted future extension from Standard v7. Data-layer tenant isolation for multi-tenant constellations. Logic-layer controls are already specified: the Auth Gate stamps packets with tenantId, scoped subscriptions filter delivery by tenant, and RBAC predicates enforce record-level access. What is not yet formalized is how tenant isolation is enforced at the storage layer — ensuring Tenant A's records are physically or logically separated from Tenant B's in the database. For Postgres-based constellations, the mechanisms are well-understood (Row Level Security policies, schema-per-tenant, separate databases). Because all database access is concentrated in Vault Loops, a formal tenant scoping pattern would affect exactly one loop type. Will be specified when a real multi-tenant project requires it. See also: Auth Gate, Scoped Subscription, Vault Loop, Role-Permission Matrix

The Bequest MMT — In the Projects-System, the minimal Charter residue: a field belongs to a project's Charter only if it cannot be recomputed from the rest of byte-truth (the repo excluding the Charter). Everything with conditional entropy zero against that rest is render, not Charter — so the Bequest is exactly what the successor cannot derive and must be told. The decidable test ("can the successor recompute this? if yes, it does not belong") is the whole discipline. See also: Charter, the Projects-System, The Headwaters.

The Cistern MMT — The spare-context forward-prep convention (christened S16.1634, operator ratify): the artifact a Freshet pours into at close — poured after the handoff is safe and only if tank remains. It carries the re-derivable-but-costly prep the handoff structurally can't, above all the pre-run \ X-family harvest (CX · KX · SX · TX · PX), pourable receipts only (provisioning-over-summary; v1.1) — pour each reflex's byte-truth-stable receipt, flag its session-local residue (TX's runtime T0, PX's actual next-focus) derive-fresh at open. Priority-ordered harvest-first. Companion to the handoff, never a replacement (the handoff wins on any conflict); empty is valid, fabricated never. See also: The Ember Gate, the handoff, CX, X, the pourability rule.

The Consent-First Default DEV — Standing Principle (PiF, S24.1515): every paid thing Loop World ships is OFF by default — no dollar moves without a live, unexpired consent event created this term. Auto-renew is opt-in only, comprehension-gated (one informed sentence, receipted — not buried clicks), and never a permanent grant (it self-renews with announcement). Dormancy suspends billing, never access (stasis); revival grants a real free term ( the Fallow Credit). The default is constitutional, not configurable — flipping it is a Creed-level amendment on the record, never a growth toggle. The honesty is the delight, the delight is the marketing — one hold. Two new build leaves (dormancy detector, friction receipt); everything else reuses the Warrant (expiring grants), the Ledger (reversing-entry gift), the Dwell (reversal-indexed opt-in), and the lifecycle states. The operational face of the Creed recognition The Perishable Grant. See also: The Perishable Grant, The Fallow Credit, The Warrant, the Dwell, Feast Line, Monument Principle.

The Fallow Credit DEV — The named return-from-stasis gift in The Consent-First Default (S24.1515): when a customer whose account went to STASIS (billing suspended for non-use, access never revoked) picks it back up, they get a free term — because they'd already paid for a term they never used, so we call it square. Posted as a Ledger reversing entry (proof-chain intact — "the gift is real" invariant), not a promise. Named for the acequia's fallow provision (Sol): no ditch-tax for a fallow season, and your water right waits for you. Named because named things travel — "You've got a Fallow Credit" is a sentence a person repeats; "they refunded my unused time" is forgotten by lunch. The screenshot moment; the free-marketing engine (Kira: our billing moments are the marketing). See also: The Consent-First Default, The Perishable Grant, stasis.

the Gatehouse DEV — The census home of the Gate: every gate in the corpus read as an instance of the one seven-field spine. The Liner Notes DEV — A session-end protocol for musical composition. The musical complement to the ice breaker: one opens the session with play, the other closes it with art. Origin: S~163. See also: Session Opening Protocol, FWW(C)

the Pawl MMT — The one genuine new discipline inside The Capstan, and its soul: the FBD against record-drift. Record-drift has a single root shape (Kaleidoscope #030) — the record-update is a separate manual step AFTER the act, so it is the first thing dropped when the tank runs low. The Pawl's fix is not a better detector but a rule: the record-update RIDES the act that creates it, so doing the work is updating the record. A capstan's pawl catches every turn so the load cannot slip back; the Pawl catches every station that has a tool-seam to hang it on (Intake= notes.py add, Work=the Commit-Cadence push-per-beat, Mop Up=the byte-presence predicate exit-5, Deploy= making_deploy_hook.py, Verify=distinct landed/live states, Report= buffer_append.py per beat). It names and generalizes loop-wide a move the corpus already made at single stations (the Commit-Cadence, the Close-Buffer, the making-ledger deploy gate). Two sub-rules: a record describes a change by its shape, not by quoting the copy it retired (the substring-match trap), and names machinery by role, not by private path (the redact gate). Honest ceiling: it makes the record ride the act where a seam exists — it cannot force a Note that was never spoken, nor prove an authored why is true, only that the record is present and byte-anchored; visibility, not immunity, the operator the witness. See also: The Capstan, the Commit-Cadence, The Close-Buffer, The Making, the Blaze.

The Proper Time DEV — The christened name (operator, S08.2007-velvet-yeti-emkpps) of the Forest-wide time system (DP-031, DESIGN ONLY — no build authorized): the whole-system model of time across calendar/mail/butcher/contacts/reminders and the multi-user architecture. Three kinds of time (Instant / Floating / Zoned); the one law — store the IANA zone identity ( America/New_York), never a bare offset (a DST snapshot that rots); two anchors — a per-tenant signed home zone + events carrying their own zone; multi-user renders event-zone → viewer-home-zone (M2 ⇒ no shared clock). Named for the relativity term: proper time is the time each observer measures along their own worldline — there is no universal "now," and comparing two observers means transforming between their frames, which is the design's multi-user rule verbatim. Namecheck note: the phrase is shared by unrelated external products (a relativity app; a SaaS time-tracker "ProperTime"); the overlap was surfaced before the pen and operator-accepted as immaterial for an internal Forest name (peer of the Sexton / the Cairn). Buildable-next: Slices 0–2, operator-gated. See also: DP-031, the Forest, DESIGN ONLY, the multi-user architecture.

The Steep DEV — A cognitive state modifier applied to the Advisory Board via bracket syntax: [cannabis], [mushrooms], [lsd], [molly], [caffeine], [adderall]. The Vanishing Ball DEV — The Super RCR (S05) that proved the Constraint drive geometrically. The volume of the unit n-ball, V(n)=π^(n/2)/(n/2)!, rises to a crest near n\ ≈5.26 and then falls toward zero as more dimensions are added — capability is not monotonic in dimension, so past the crest, adding makes the system worse. Registered nball in The Math in Force as its first LOAD-BEARING result. The operator's framing is kept verbatim: "we walked backwards into it, but that does not mean we're still not held up by the equation" — the discipline was built first and the theorem found beneath it; the order of discovery does not change what holds the building up. See also: The Math in Force (MiF), the reckoner, The Creed*

thermostat DEV — Pre-kill diagnostic in the Astrolabe program. At build 5 of instrumented builds: is anyone reading the instrument data? Translator (Pattern) MMT — The data-scrubbing half of a loop that adopts an external dependency speaking a foreign data model — a payment processor webhook format, a legacy SOAP API, an OIDC provider's token structure. The Translator receives raw external data, validates it against the external provider's schema, maps it to the internal packet contract, and emits clean packets indistinguishable from any other packet on the bus. The translation logic is isolated inside the loop's closure — no other loop knows or cares that the data originated externally. The Translator formalizes two distinct responsibilities that share the same loop: the Translator handles what happens when the external system responds; the Dependency Gate handles what happens when it is unreachable. Both should be declared in the Constellation Spec, making the data-scrubbing responsibility a design-time decision visible in the spec rather than an implementation detail discovered during coding. Added in Standard v7. See also: Dependency Gate, Adopted Dependency, Packet Contract Registry, Filter Loop

Trunk ARCH — One of three tool levels in the Tree Catalog. Trunk tools are shared resources that appear across multiple trees. Each has a primary tree (where it anchors or has its strongest role) and secondary trees (where it serves as a member). 15 Trunk tools: Contact, CMS, Calendar, Pulse, Flare, Analytics, Tome, Commerce, Scheduling, Forms, Email, Compliance, Tracker, Bridge, Sync. See also: Root, Branch, Tree Catalog, Tree

Vault Loop MMT — One of seven loop types. The Memory Slot analog. The only loop type that receives a reference to the persistence layer. Narrow interface: store, retrieve, update, delete, confirm. No other loop can touch the database because no other loop has been given the database client. Receives bus and db as capabilities. See also: Memory Slot

WO (Work Order) DEV — A structured production task dispatched to a parallel vanilla Claude tab. Carries task description, source files, output specs, verification criteria. The division of labor: architectural work in advisory session, mechanical production via WO. Chaining (Flume) supports DAG workflows. See also: The Shuttle
